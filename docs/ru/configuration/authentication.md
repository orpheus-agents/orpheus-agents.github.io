# Авторизация агента

Создайте авторизацию в **Настройки → LLM-аккаунты**. Задайте название, харнес и режим авторизации, затем выберите аккаунт в одном или нескольких [профилях](profiles.md). Режим и хранилище нельзя изменить после создания. Для другого режима создайте аккаунт и перенесите на него профили.

## API-ключ {#api-key}

Выберите **API-ключ** и введите ключ провайдера. Orpheus шифрует его в БД с помощью [`ENV_ENCRYPTION_KEY`](../reference/environment.md#env-env-encryption-key). API и worker должны использовать общий ключ шифрования. Ключи провайдера не нужно добавлять в окружение процессов или [`sandbox.env_from`](../reference/api/create-session.md).

В карточке аккаунта отображается маска. Для замены введите новый ключ. API не возвращает прежний ключ, а форма не подставляет его в поле замены.

## Аккаунт {#account}

Настройте приватное S3-совместимое хранилище в [`orpheus.toml`](../reference/profiles.md#store-access):

```toml
[credential_stores.main]
type = "s3"
bucket = "orpheus-credentials"
region = "us-east-1"
```

Для своего S3-сервиса задайте [`endpoint_url`](../reference/profiles.md#store-endpoint-url). Передайте **API и worker** стандартные AWS credentials, например [`AWS_ACCESS_KEY_ID` и `AWS_SECRET_ACCESS_KEY`](../reference/profiles.md#store-access). Нужны права чтения и записи объектов авторизации. Хранилище должно возвращать `ETag` и поддерживать условную запись с `If-Match`.

Выберите режим **Аккаунт**, укажите хранилище и вставьте содержимое действующего Codex `auth.json` в форму. Orpheus генерирует имя объекта из UUID аккаунта. Профили одного аккаунта используют общую авторизацию.

Нажмите **Редактировать авторизацию**, чтобы загрузить или заменить файл. Это действие показывает его токены текущему пользователю. При конфликте изменений черновик сохраняется. Для новой попытки записи нужно явно перечитать файл. Неизвестные поля JSON сохраняются.

Orpheus синхронизирует обновлённые токены обратно в S3. Новый процесс агента читает актуальный файл. Уже работающий процесс не перечитывает его автоматически после ручной замены. Перенос профиля на другой аккаунт не меняет привязку существующих сессий.

Удалить аккаунт можно, только если на него не ссылаются профили и сессии. Удаление убирает запись БД и секрет API-ключа, но оставляет файл в S3. [Карточки аккаунтов и лимиты](../web/limits.md).

## Сетевой прокси {#network-proxy}

[`SANDBOX_PROXY_URL`](../reference/environment.md#env-sandbox-proxy-url) задаёт прокси процесса агента. HTTP и HTTPS заполняют `HTTP_PROXY` и `HTTPS_PROXY`. SOCKS5 и SOCKS5H заполняют `ALL_PROXY`. `NO_PROXY` оставляет `localhost` и `127.0.0.1` без прокси. Пустое значение отключает подстановку прокси Orpheus.

По умолчанию используется HTTPS-прокси AgentBox. Для SOCKS5 с разрешением DNS на прокси задайте `socks5h://sandbox-proxy.agentbox.ru:65180`. Поддержка SOCKS зависит от установленного харнеса и режима авторизации. Для аккаунтной авторизации ChatGPT оставьте HTTPS, пока не проверите свою комбинацию: в проверке совместимости Codex 0.164.0 работал через SOCKS5 с API-ключом, а с аккаунтной авторизацией завершался ошибкой `workspace routing discovery failed`.

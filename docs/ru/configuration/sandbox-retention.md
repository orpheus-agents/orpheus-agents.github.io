# Хранение песочниц на паузе

Между запусками переиспользуемая сессия сохраняет песочницу на паузе. Orpheus удаляет старые песочницы, чтобы освободить их снимки. История запусков, сообщения, результаты и расход токенов остаются доступны. Файлы, процессы и контекст агента, которые хранились только в удалённой песочнице, восстановить нельзя.

## Настройка worker

| Настройка | По умолчанию | Допустимые значения |
| --- | --- | --- |
| [`SANDBOX_PAUSED_RETENTION_DAYS`](../reference/environment.md#env-sandbox-paused-retention-days) | 14 дней | Целое число от 1 до 100 включительно |
| [`SANDBOX_CLEANUP_BATCH_SIZE`](../reference/environment.md#env-sandbox-cleanup-batch-size) | 1000 сессий за проход | Положительное целое число |

::: warning Выберите срок хранения до запуска worker
Уборка начинается при старте worker и применяется к существующим сессиям на паузе. Просроченные песочницы могут попасть уже в первую пачку. Удаление необратимо уничтожает файлы и контекст агента, хранившиеся только в этих песочницах.
:::

Задайте переменные в окружении worker. В Compose после изменения [пересоздайте контейнер worker](../operations/maintenance.md). Обычный restart не подхватывает новые ENV. Некорректные значения не позволят процессу запуститься. Изменение срока применяется и к существующим сессиям на паузе.

Срок отсчитывается от [`finished_at`](../reference/api/get-run.md) последнего запуска, включая ошибку и отмену. День — 24 часа. Это время после завершения запуска, а не точная длительность физической паузы. Следующий завершённый запуск начинает отсчёт заново. Чтение истории и повтор уже принятого запроса срок не продлевают.

Например, при настройке по умолчанию сессия подходит для удаления, когда с завершения её последнего запуска прошло больше 14 дней. Проверка выполняется при старте worker и каждые четыре часа. За проход выбирается не больше настроенного лимита сессий, включая повторы. Одновременно удаляются не больше трёх песочниц. Очередь или ошибка провайдера могут задержать удаление. Шесть проходов с интервалом четыре часа выбирают за сутки до шести размеров пачки, включая повторы.

Активные сессии исключаются. Уборка не занимает слоты исполнения и не возобновляет песочницы. Неудачные удаления повторяются в следующих проходах, в том числе после перезапуска worker.

## Продолжение после удаления

[Состояние песочницы](../reference/api/get-session.md) меняется с `paused` через `deleting` на `deleted`. Ошибка песочницы `sandbox_expired` объясняет причину удаления. При неудачной попытке появляется `sandbox_delete_failed` до успешного повтора. Результат последнего запуска не меняется.

[Создание запуска](../reference/api/create-run.md) в переиспользуемой сессии с состоянием песочницы `deleting`, `deleted` или `unavailable` возвращает `409 session_unavailable`. Создайте новую сессию с контекстом, необходимым для новой задачи. Orpheus не создаёт окружение заново внутри старой сессии.

Если песочницу удалили извне и Orpheus ещё не обнаружил потерю, API может вернуть `202`. После подтверждения потери worker завершит запуск с `sandbox_lost`. Не повторяйте автоматически задание, которое уже могло выполнить действия. Повтор ранее принятого запроса с тем же [ключом идемпотентности](../reference/api/conventions.md#запросы) по-прежнему возвращает исходное подтверждение.

[Продолжение в Mattermost](../integrations/mattermost/conversation.md) и [сброс контекста в Space](../space/schedules.md#пауза-и-контекст) описывают обработку следующего запроса в коннекторах. Режим сессии [`allow_multiple_runs`](../reference/api/create-session.md) не гарантирует доступность её песочницы.

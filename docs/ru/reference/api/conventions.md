# Правила HTTP API

Передавайте сервисный ключ заголовком `Authorization: Bearer …`. В примерах `ORPHEUS_URL` содержит origin сервера, методы начинаются с `/api/v1`.

## Запросы

- Для JSON задавайте `Content-Type: application/json`.
- Для создания сессии, запуска и уточнения используйте `Idempotency-Key`.
- `202` означает приём задачи. Читайте состояние запуска для результата.
- Времена передаются в RFC3339, идентификаторы сессий и запусков являются UUID.
- Курсоры непрозрачны. Следуйте [`next_cursor`](list-sessions.md) и [`has_more`](list-sessions.md), где оно предусмотрено. При смене фильтров начинайте с первой страницы.

## Ошибки

| HTTP | Что проверить |
| --- | --- |
| 400 | Формат запроса или курсора |
| 401 | Bearer-ключ или браузерную сессию |
| 403 | Права режима доступа, cookie даёт только чтение |
| 404 | Идентификатор ресурса |
| 409 | Состояние сессии, конфликт ключа или исчерпанный бюджет |
| 413 | Размер запроса |
| 415 | Content-Type |
| 422 | [`error.details`](schema-error.md) с указанием поля |
| 503 | Ёмкость исполнения или доступность сервиса |

Точный код ошибки находится в [`error.code`](schema-error.md). Повторяйте неопределённый сетевой результат с прежним телом и ключом. Не повторяйте некорректный запрос без исправления.

Явный неверный Authorization не заменяется браузерной авторизацией. Пустой [`PUBLIC_API_KEYS`](../environment.md#env-public-api-keys) отключает сервисные команды в режимах `anonymous` и `saml`.

## Выбор сервисов

[Коды сервисов](../../configuration/secrets.md#services) не зависят от порядка и не должны повторяться. Неизвестный код возвращает `422 unknown_service` до принятия запроса. Повтор с прежним ключом идемпотентности и вводом возвращает принятый результат без обращения к текущему каталогу. Ответы содержат неизменяемые снимки сервисов и объединённые имена ENV без значений секретов.

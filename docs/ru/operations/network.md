# Домен, HTTPS и доступ к API

Веб-контейнер обслуживает сайт и проксирует `/api/`, `/auth/` и `/saml/` в Orpheus. Браузер обращается к одному origin. `ORPHEUS_UPSTREAM` задаётся на web и содержит внутренний адрес API без суффикса пути.

## Подключите домен

1. Направьте DNS-имя, например `orpheus.example.com`, на сервер.
2. Выпустите TLS-сертификат на вашем reverse proxy.
3. Проксируйте весь сайт на web, в комплекте это `127.0.0.1:8085`.
4. Сохраните заголовки Host, Origin, Cookie и Set-Cookie.
5. Отключите буферизацию SSE и увеличьте таймаут чтения для долгих соединений.
6. Настройте SSO до открытия доступа сотрудникам.

Для nginx ключевые параметры location:

```nginx
location / {
    proxy_pass http://127.0.0.1:8085;
    proxy_set_header Host $host;
    proxy_set_header X-Forwarded-Proto $scheme;
    proxy_buffering off;
    proxy_read_timeout 3600s;
}
```

Это фрагмент уже настроенного HTTPS-сервера nginx. TLS-конфигурация и сертификаты задаются отдельно.

API-ключи предназначены для сервисных запросов. Не внедряйте общий Bearer-токен в JavaScript или reverse proxy браузера. Внутренний API можно предоставить коннекторам отдельно.

Системный порт 9100 и PostgreSQL не нужны публично. Доступ к содержимому сессий определяется [режимом браузерной авторизации](sso.md).

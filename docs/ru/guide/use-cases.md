# Возможности и сценарии

Начните с процесса, в котором понятны входные данные, ожидаемый результат и ответственный за проверку.

| Задача | Что делает агент | Что нужно подключить |
| --- | --- | --- |
| Подготовка ответа по тикету | Читает обращение, находит сведения и готовит внутренний комментарий | API хелпдеска и база знаний |
| Разбор ошибки | Сопоставляет описание проблемы, документацию и доступные логи | Инструмент чтения логов и документация |
| Отчёт по данным | Обрабатывает таблицу, считает показатели и возвращает файл | Вложение или API источника |
| Помощь разработчику | Изучает репозиторий, готовит изменения и объясняет результат | Git, доступ к репозиторию и инструкции |
| Регулярная сводка | По расписанию собирает данные и готовит сводку | [Space](../space/overview.md) и API источника |

Это примеры настройки агентов. Доступ к каждой системе нужно предоставить через API, CLI или MCP. Готовый коннектор Mattermost отвечает за получение задач и доставку результатов.

## Как провести пилот

1. Выберите один процесс и небольшой круг пользователей.
2. Определите результат: проект ответа, файл отчёта или выполненное действие.
3. Дайте агенту необходимые инструменты и инструкции.
4. Проверьте несколько обычных случаев и случаев с неполными данными.
5. Оцените полезность результата, время выполнения и расход токенов в веб-интерфейсе.

[Пример с хелпдеском](../integrations/custom/helpdesk.md) показывает два способа публикации результата.

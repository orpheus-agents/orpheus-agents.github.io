# Эксплуатация Space

## Процессы и проверки

Образ Space запускается командами `serve`, `worker` и `migrate up`. API можно масштабировать независимо. Worker должен быть один: второй процесс завершится, если первый уже работает. В Kubernetes используйте для worker одну реплику и стратегию `Recreate`.

API и worker имеют отдельные системные HTTP-порты, по умолчанию [`9100`](../reference/space.md#service):

| Проверка | Назначение |
| --- | --- |
| `/health` | Процесс отвечает |
| `/ready` | Готовность процесса и БД с применёнными миграциями |

Пробы доступны во внутренней сети. Не публикуйте системный порт вместе с пользовательским API. Готовность сама по себе не подтверждает доступность Orpheus или провайдера модели.

Выполняйте команды из каталога примера Space. При [локальном подключении](local-core.md) сохраните `COMPOSE_FILE` в `.env`:

```sh
docker compose ps
docker compose logs --tail=100 api worker migrate
curl -fsS http://localhost:9110/ready
```

## Данные и обновление

Резервируйте БД Space отдельно от БД Orpheus. В Space находятся задания, история срабатываний и сессии браузера. Сообщения и полные результаты хранятся в Orpheus. Сохраняйте также конфигурацию, SAML-пару и API-ключи в принятом у вас хранилище секретов.

Для обновления примера остановите worker, измените версии образов в `.env`, выполните миграции и запустите процессы:

```sh
docker compose stop worker
docker compose --profile execution pull
docker compose run --rm migrate
docker compose up -d api web worker
```

Перед обновлением сделайте резервную копию. После него проверьте readiness, вход и ближайшее срабатывание. После простоя исполняется только последнее актуальное срабатывание. [Поведение заданий](schedules.md).

## Диагностика {#diagnostics}

Смотрите отдельно [`state`](../reference/space-api/schema-occurrencestate.md) отправки и [`run_status`](../reference/space-api/schema-occurrence.md) выполнения в Orpheus.

| Состояние отправки | Значение |
| --- | --- |
| `pending` | Срабатывание ожидает отправки |
| `dispatching` | Запрос отправляется или его исход уточняется |
| `accepted` | Orpheus принял запуск. Итог смотрите в `run_status` |
| `skipped` | Срабатывание пропущено |
| `failed` | Отправка завершилась ошибкой |
| `cancelled` | Ожидавшая отправки работа отменена |

В карточке [`observed_at`](../reference/space-api/schema-occurrence.md) показывает, когда Space последний раз получил состояние Orpheus. `sync_error_code` обозначает ошибку последующей синхронизации. Прежний статус при этом сохраняется. `run_error_code` относится к выполнению агента, а `error_code` — к отправке срабатывания.

| Симптом | Действие |
| --- | --- |
| `dispatching` с `core_unavailable` | Проверьте адрес и сетевую доступность Orpheus из Space. Worker может оставаться `healthy` |
| Нет новых срабатываний | Проверьте статус задания, часовой пояс, worker, его readiness и связь с Orpheus |
| `run_not_found` / `session_not_found` | Проверьте адрес Orpheus и восстановите доступ к исходному запуску. Отсутствие записи не доказывает завершение, поэтому новые запуски блокируются |
| Результат отвечает `503` | Проверьте [адрес и ключ Orpheus](../reference/space.md#core) на Space API. История при этом остаётся доступной |
| `403` при сохранении | Сверьте browser origin с [публичным URL](../reference/space.md#access) и прохождение CSRF-заголовка через прокси |
| `422` при сохранении сервисов | Кода нет в [каталоге ядра](../configuration/secrets.md#services). Выберите доступный сервис или обновите каталог |
| Отправка `failed`, код `unknown_service` | Выбранный сервис удалён до отправки. Исправьте выбор или восстановите запись каталога |
| Запуск принят, затем завершился ошибкой из-за ENV | Передайте значение переменной worker Orpheus и проверьте ошибку запуска |
| Сброс контекста отвечает `409` | Дождитесь завершения или восстановления синхронизации активного запуска |

## Если запись запуска потеряна

Проверьте, что Space подключён к исходному Orpheus, а не другой инсталляции. Восстановите запись из резервной копии вместе с данными Orpheus. После успешного чтения конечного статуса Space продолжит планирование.

Если восстановить данные невозможно, проверьте состояние отправки:

- **`accepted`**: Orpheus уже принял запуск, Space повторно его не отправит. Убедитесь, что прежняя работа не выполняется и не сможет возобновиться. Затем удалите задание и создайте новое. История старого задания сохранится. Space может продолжать попытки чтения потерянного запуска, но они не блокируют новое задание.
- **`dispatching`**: исход отправки неизвестен. Удаление задания не прекращает попытки отправки. Сначала восстановите связь с исходным Orpheus и выясните исход запроса. До этого не создавайте замену, чтобы не запустить работу дважды.

[Получение результата](../reference/space-api/get-occurrence-result.md) не перезаписывает сохранённую историю. [Поля и коды ошибок](../reference/space-api/conventions.md#history).

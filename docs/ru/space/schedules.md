# Задания и результаты

## Создайте задание

В разделе **Задания** задайте название и поручение агенту. Включите в поручение источники, нужные ограничения и место публикации результата. Новый запуск не получает переписку, в которой обсуждали задание. Если нужен конкретный канал или документ, укажите его явно.

Выберите повторение: каждый день, по будням, в выбранные дни, раз в месяц, через заданное число часов или минут. Для других правил доступен пятичастный [cron](../reference/space-api/schema-createschedule.md). Например, `0 10 * * 1-5` означает 10:00 по будням.

Новое задание берёт часовой пояс из настроек интерфейса. Проверьте его и пять ближайших срабатываний перед сохранением. Изменение часового пояса в шапке влияет на отображение дат, но не меняет часовой пояс уже созданных заданий.

| Настройка | Когда использовать |
| --- | --- |
| Работает / Пауза | Включить будущие срабатывания или приостановить их |
| Новая сессия для каждого запуска | Выполнять каждое поручение с чистым контекстом |
| Продолжать одну сессию | Сохранять контекст между запусками |
| Профиль | Выбрать [конфигурацию агента](../configuration/profiles.md) |
| Шаблон песочницы | Выбрать [окружение AgentBox](../configuration/templates.md) |
| Модель | Необязательная замена модели выбранного профиля |
| Email владельца | Определить владельца и фильтровать список. Пустое значение — общее задание |

Веб-интерфейс заполняет владельца email из [SSO](access.md). У обычного пользователя поле доступно только для чтения. Администратор может изменить его или очистить для общего задания. При создании по API-ключу без [`owner_email`](../reference/space-api/schema-createschedule.md) задание остаётся общим. При запросе обычного пользователя с cookie пропуск поля подставляет email сессии.

Профили и шаблоны загружаются из каталогов Orpheus. Новые задания используют настроенные значения по умолчанию, существующие сохраняют свой выбор. Для создания задания или смены этих настроек Orpheus должен быть доступен.

[Поля API и допустимые значения](../reference/space-api/schema-createschedule.md).

## Сервисы {#environment}

Выберите системы, нужные агенту, в поле [`services`](../reference/space-api/schema-createschedule.md) задания. В списке выбора показаны названия и описания. Раскройте блок под списком, чтобы посмотреть имена ENV выбранных сервисов. Значения секретов не показываются и не хранятся в Space. В просмотре задания названия сервисов выведены в одну строку. Наведение, фокус с клавиатуры или нажатие открывает описание и имена ENV.

Для доступного вам на редактирование задания можно выбрать любой сервис каталога. Автоматического выбора нет. Пустой список означает отсутствие сервисов. Если нужной системы нет, попросите администратора [настроить сервис](../configuration/secrets.md#services).

Недоступные или удалённые сервисы остаются видны по коду: их можно сохранить или убрать. Без каталога можно сохранить прежний выбор или очистить все сервисы. Любой изменённый непустой список, включая удаление части кодов, требует проверки в Orpheus. Возобновление с паузы также проверяет весь выбор. Другие поля остаются доступны для редактирования без каталога сервисов. Изменение выбора начинает новую переиспользуемую сессию при следующем подходящем выполнении. Если администратор изменил состав ENV сервиса под прежним кодом, примените **Сбросить контекст**, чтобы использовать новый состав в продолжаемой сессии.

## Пауза и контекст

Пауза и удаление прекращают будущие срабатывания, но не отменяют уже принятый Orpheus запуск. После возобновления выбирается будущее время. После простоя Space выполняет только последнее актуальное срабатывание, без очереди за каждый пропуск.

Если прошлый запуск ещё выполняется, очередное срабатывание пропускается. При неизвестном исходе Space дожидается выяснения исхода, чтобы избежать повторного выполнения. Ошибка самого агента не вызывает автоматический повтор.

**Сбросить контекст** начинает новую сессию при следующем запуске. Пока есть активный запуск, сброс недоступен. [Точные правила повторения и сохранения контекста](../reference/space-api/conventions.md#execution).

## История и результат

В списке виден последний запуск. В истории различаются принятие задания Orpheus и выполнение агента: `accepted` ещё не означает успешное завершение.

Карточка показывает сохранённый статус, время наблюдения и ошибки синхронизации. Кнопка результата отдельно обращается к Orpheus. Если Orpheus недоступен, история остаётся читаемой. Повторите получение результата после восстановления связи.

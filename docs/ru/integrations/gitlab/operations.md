# Результаты и эксплуатация

## Прочитайте результат

Коннектор публикует подтверждённые замечания в обсуждениях MR и добавляет итоговый комментарий. Проверки агента, вывод инструментов и ошибки хуков смотрите в полной [истории сессии](../../web/history.md). Финальный ответ агента остаётся в этой истории и не копируется автоматически в GitLab.

При следующих ревью коннектор может обновлять свои обсуждения, закрывать исправленные замечания и сообщать о повторившихся проблемах. Обсуждения людей и назначения других ревьюеров он сохраняет.

Если во время анализа изменился diff, MR закрыт или бот снят с ревью, коннектор отменяет или отбрасывает устаревшую работу. Он не публикует старое ревью к изменённому diff. Для новой проверки после завершения или ошибки назначьте бота снова. Неудачный анализ автоматически не повторяется.

## Запускайте один экземпляр

На одну инсталляцию GitLab и учётную запись бота должен работать ровно один коннектор. Остановите старый процесс перед запуском нового. Увеличение числа реплик не повышает поддерживаемую параллельность ревью. Настраивайте [`MAX_CONCURRENT_REVIEWS`](../../reference/gitlab-review.md#env-max-concurrent-reviews) с учётом ресурсов Orpheus и квот провайдеров.

У коннектора нет HTTP API и endpoint проверки здоровья. Отдельная БД ему не нужна. Следите за состоянием процесса и JSON-логами в stdout. Ошибки конфигурации, запуска и выполнения завершают процесс с кодом `1`. Подробность логов задаёт [`LOG_LEVEL`](../../reference/gitlab-review.md#env-log-level).

При остановке коннектора принятые запуски Orpheus продолжаются. После перезапуска коннектор находит их и продолжает публикацию. Временные ошибки публикации повторяются без нового анализа.

Для обновления [примера Compose](connect.md) измените версию образа в `.env`, затем:

```sh
docker compose pull
docker compose stop review
docker compose up -d review
docker compose logs --tail=100 review
```

## Проверьте проблему

| Симптом | Что проверить |
| --- | --- |
| Коннектор завершается при старте | JSON-лог ошибки, обязательные [настройки подключения](../../reference/gitlab-review.md#connections), доступность каталога workflows и [корректность файлов](../../reference/gitlab-review.md#validation) |
| Назначенный MR не запускается | Доступ бота, назначение ревьюером, открытое состояние MR, [интервал опроса](../../reference/gitlab-review.md#env-poll-interval-seconds) и [лимит параллельности](../../reference/gitlab-review.md#env-max-concurrent-reviews) |
| Сообщение о пропуске в GitLab | Добавьте проект в [workflow](workflows.md), перезапустите коннектор и назначьте бота снова |
| Не создаётся сессия | Существование профиля, шаблона и кодов сервисов, ключ API и [лимит размера запроса](../../reference/gitlab-review.md#env-max-session-request-bytes) |
| Ошибка `before_run` | Доступ clone/fetch по HTTPS, необходимые инструменты в песочнице и изменение MR во время подготовки |
| Агент закончил, но результат не опубликован | `after_run`, логи коннектора и права API GitLab. Одного финального ответа недостаточно для публикации ревью |
| В сообщении об ошибке нет ссылки на сессию | Задайте публичный [адрес веб-интерфейса](../../reference/gitlab-review.md#env-orpheus-web-base-url). Если ошибка произошла до создания сессии, ссылки не будет |

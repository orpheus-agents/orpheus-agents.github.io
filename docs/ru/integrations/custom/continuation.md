# Продолжение задачи и уточнения

Сохраните связь тикета с [`session_id`](../../reference/api/get-session.md). При новом событии сначала проверьте, завершился ли предыдущий запуск.

Для следующих запусков сессия должна быть создана с [`allow_multiple_runs: true`](../../reference/api/create-session.md). В режиме по умолчанию создавайте новую сессию на следующую задачу. Уточнения работающему агенту доступны в обоих режимах.

## Как проверить состояние

Вызовите [получение сессии](../../reference/api/get-session.md), подставив её ID вместо `{sid}`:

```http
GET /api/v1/sessions/{sid}
```

В ответе [`active_run_id`](../../reference/api/get-session.md) содержит ID незавершённого запуска или `null`, если такого запуска нет. Поля [`status`](../../reference/api/get-session.md) и [`phase`](../../reference/api/get-session.md) описывают последний запуск. Например, такой фрагмент ответа означает, что агент работает:

```json
{
  "allow_multiple_runs": true,
  "active_run_id": "8a61a76c-73bf-4cbd-a501-26d2f5fcb7a1",
  "status": "running",
  "phase": "agent"
}
```

Выберите действие по состоянию:

| [`status`](../../reference/api/schema-runstatus.md) | Что происходит | Действие коннектора |
| --- | --- | --- |
| `accepted`, `starting` | Задача принята, окружение и хуки готовятся к работе агента | Сохранить новое сообщение и повторить проверку состояния через несколько секунд |
| `running` | Агент работает | Передать [уточнение](#уточнение-во-время-работы), подставив ID активного запуска вместо `{rid}` |
| `cancelling`, `finalizing` | Запуск останавливается или завершает работу, в том числе хук после агента | Сохранить сообщение и дождаться завершения запуска |
| `completed`, `failed`, `cancelled` | Запуск завершён, активного запуска нет | [Создать следующий запуск](#следующая-задача), если разрешены повторные запуски, иначе новую сессию. При ошибке сначала проверить её причину |

Наличие [`final_message`](../../reference/api/get-session.md) ещё не означает, что запуск завершён: ответ агента может быть готов, пока выполняется [`after_run`](../../configuration/hooks.md#hook-after-run). Ориентируйтесь на состояние запуска.

Для подробностей конкретного запуска вызовите [получение запуска](../../reference/api/get-run.md). Возьмите его ID из [`active_run_id`](../../reference/api/get-session.md) или [`last_run_id`](../../reference/api/get-session.md), если запуск уже завершён.

## Если запрос отклонён

Состояние может измениться между проверкой и отправкой сообщения. Смотрите [`error.code`](../../reference/api/conventions.md#ошибки) в ответе API:

- `409 session_busy`: уже есть незавершённый запуск. Перечитайте сессию и выберите действие по таблице.
- `409 multiple_runs_not_allowed`: сессия рассчитана на один запуск. Создайте новую сессию с нужным контекстом.
- `409 run_not_accepting_messages`: запуск не принимает уточнения. Сохраните сообщение, перечитайте сессию и дождитесь подходящего состояния или создайте следующий запуск, если предыдущий завершён.
- `409 session_unavailable` или `409 token_limit_exceeded`: окружение недоступно или бюджет сессии исчерпан. Создайте новую сессию с необходимым контекстом. Так же поступайте, если завершившийся запуск сообщил об утрате контекста — [`error.code: context_lost`](../../reference/api/get-run.md).

Для каждой операции используйте собственный [`Idempotency-Key`](../../reference/api/conventions.md#запросы), стабильный при повторе. При сетевом таймауте повторите тот же запрос с тем же телом и ключом, чтобы выяснить, был ли он принят. [Подробнее о повторах](reliability.md).

## Остановка

Для остановки вызовите [отмену запуска](../../reference/api/cancel-run.md). Отмена не откатывает изменения, которые агент уже сделал во внешней системе.

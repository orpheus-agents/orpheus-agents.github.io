# Повторы и восстановление

Webhook может прийти дважды. Ответ на создание сессии может потеряться после того, как Orpheus принял задачу. Обрабатывайте эти ситуации как штатные.

## Приём задачи

- Привяжите [`Idempotency-Key`](../../reference/api/conventions.md#запросы) к устойчивому ID события источника.
- При таймауте повторите тот же запрос с тем же телом и ключом.
- Для нового события создайте новый ключ.
- При `409 idempotency_conflict` проверьте, почему один ключ использован с разными данными.

[`external_key`](../../reference/api/create-session.md) и [`input_fingerprint`](../../reference/api/create-session.md) помогают найти объект и версию входных данных. Они не устраняют дубли запросов.

## Доставка результата

Сохраняйте связь `source_event_id → session_id → run_id` и отметку публикации результата. Для комментария используйте ключ, зависящий от запуска или операции хука. Если API целевой системы не поддерживает идемпотентность, проверяйте сохранённый ID комментария или маркер перед повторной отправкой.

Не обещайте ровно одну доставку между независимыми системами без соответствующего протокола. Неопределённый результат отправки требует сверки с целевой системой.

При [`503 capacity_exhausted`](../../configuration/limits.md) повторяйте запрос с задержкой и разбросом. При `422` исправьте данные. После рестарта восстановите незавершённые задачи по сохранённым ID и состоянию Orpheus.

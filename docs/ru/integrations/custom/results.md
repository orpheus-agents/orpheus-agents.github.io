# Получение результата и событий

Для простой интеграции периодически читайте [карточку запуска](../../reference/api/get-run.md). Завершённые состояния: `completed`, `failed`, `cancelled`. Текст ответа находится в [`final_message.text`](../../reference/api/get-run.md), если итоговое сообщение есть. Проверяйте и статус, и ошибку: наличие текста само по себе не означает успех.

Для интерфейса с обновлениями используйте SSE:

```sh
curl -N "http://localhost:8000/api/v1/sessions/$SESSION_ID/events/stream" \
  -H "Authorization: Bearer $ORPHEUS_API_KEY"
```

## Восстановление после разрыва

1. Получите [историю](../../reference/api/get-history.md) и сохраните [`event_cursor`](../../reference/api/get-history.md).
2. Откройте поток с [`after`](../../reference/api/stream-events.md), равным этому курсору.
3. Сохраняйте ID обработанных событий.
4. При переподключении передайте последний ID в [`Last-Event-ID`](../../reference/api/stream-events.md). Заголовок имеет приоритет над [`after`](../../reference/api/stream-events.md).
5. При недействительном курсоре получите новый снимок истории.

История содержит сообщения и вызовы инструментов. Для полной истории следуйте [`next_cursor`](../../reference/api/get-history.md). События также доступны [обычными HTTP-запросами](../../reference/api/get-events.md).

SSE ускоряет получение обновлений. Проверка текущего состояния и сохранение отметки доставки нужны независимо от соединения. Для потока используйте отдельный HTTP-клиент без короткого таймаута обычных запросов.

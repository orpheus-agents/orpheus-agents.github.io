# Применение настроек

Проверяйте каталог workflows перед применением:

```sh
docker compose run --rm --no-deps mattermost validate
docker compose kill -s SIGHUP mattermost
```

`SIGHUP` перечитывает каталог целиком. Если один файл некорректен, остаётся предыдущая конфигурация. В Compose монтируйте весь каталог, как в быстром старте.

| Изменение | Что сделать |
| --- | --- |
| Инструкции или политика workflow | Проверить и отправить SIGHUP |
| Профиль, шаблон или состав сервиса под прежним именем | Сначала пересоздать API и worker с новой конфигурацией, затем увеличить [`revision`](../../reference/mattermost.md#workflow-revision) и применить workflow |
| ENV, токен или новое подключение | Пересоздать контейнер коннектора |
| Профили, шаблоны или сервисы в [`orpheus.toml`](../../configuration/profiles.md) | Пересоздать API и worker с одной конфигурацией |

Изменение инструкций, выбора профиля, шаблона или сервисов меняет эффективную ревизию. Перестановка кодов сервисов её не меняет. Текущая работа завершается, следующий запрос начинает новую сессию.

Отклонённый ввод сохраняется до изменения эффективной ревизии workflow. Исправив неизвестный профиль, шаблон или сервис, увеличьте `revision` и примените настройки. Коннектор повторит ввод без перезапуска. Повторные уведомления об отказе подавляются для одной ревизии, причины и ввода.

## Удаление workflow

Сначала задайте [`draining: true`](../../reference/mattermost.md#workflow-draining). Коннектор перестанет принимать новые задачи и доставит принятые результаты. Дождитесь завершения, затем удалите файл и примените конфигурацию. Немедленное удаление может отменить активную работу.

Для одного сервера Mattermost и бота запускайте один экземпляр коннектора. При обновлении заменяйте его последовательно.

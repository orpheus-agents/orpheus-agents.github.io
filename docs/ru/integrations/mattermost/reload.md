# Применение настроек

Проверяйте каталог workflows перед применением:

```sh
docker compose run --rm --no-deps mattermost validate
docker compose kill -s SIGHUP mattermost
```

`SIGHUP` перечитывает каталог целиком. Если один файл некорректен, остаётся предыдущая конфигурация. В Compose монтируйте весь каталог, как в быстром старте.

| Изменение | Что сделать |
| --- | --- |
| Инструкции или политика workflow | Проверить и отправить SIGHUP |
| Профиль или шаблон под прежним именем | Увеличить [`revision`](../../reference/mattermost.md#workflow-revision), применить workflow |
| ENV, токен или новое подключение | Пересоздать контейнер коннектора |
| Профили в [`orpheus.toml`](../../configuration/profiles.md) | Пересоздать API и worker с одной конфигурацией |

Изменение инструкций, выбора профиля или шаблона меняет эффективную ревизию. Текущая работа завершается, следующий запрос начинает новую сессию.

## Удаление workflow

Сначала задайте [`draining: true`](../../reference/mattermost.md#workflow-draining). Коннектор перестанет принимать новые задачи и доставит принятые результаты. Дождитесь завершения, затем удалите файл и примените конфигурацию. Немедленное удаление может отменить активную работу.

Для одного сервера Mattermost и бота запускайте один экземпляр коннектора. При обновлении заменяйте его последовательно.

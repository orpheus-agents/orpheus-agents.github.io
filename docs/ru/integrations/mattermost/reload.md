# Применение настроек

Проверяйте каталог workflows перед применением:

```sh
docker compose run --rm --no-deps mattermost validate
docker compose kill -s SIGHUP mattermost
```

`SIGHUP` перечитывает каталог целиком. Если один файл некорректен, остаётся предыдущая конфигурация. В Compose монтируйте весь каталог, как в быстром старте.

| Изменение | Что сделать |
| --- | --- |
| Инструкции или политика workflow | Проверить и отправить SIGHUP |
| Профиль или аккаунт | Изменить через [Настройки](../../configuration/profiles.md). Новые сессии используют обновлённый профиль и привязку аккаунта. Перезапуск не нужен |
| Состав сервиса в [`orpheus.toml`](../../configuration/secrets.md#services) | Пересоздать API и worker с новой конфигурацией. Новые сессии получат новое определение |
| Новая сборка AgentBox под выбранным именем и тегом | Новые песочницы получат обновлённую сборку. Перечитывать workflow не требуется |
| Запись каталога шаблонов, активность или описание | Изменить через [Web или API](../../configuration/templates.md#manage). Перезапуск API и worker не нужен. Принятые сессии сохраняют настройки |
| ENV, токен или новое подключение | Пересоздать контейнер коннектора |

Существующие сессии сохраняют принятые настройки и песочницу. Если текущим беседам нужен новый профиль, состав сервиса или сборка песочницы, увеличьте [`revision`](../../reference/mattermost.md#workflow-revision) и примените workflow. Следующий запрос начнёт новую сессию. Обычное обновление шаблона или инструментов не требует такого сброса.

Изменение инструкций, выбора профиля, шаблона или сервисов меняет эффективную ревизию. Перестановка кодов сервисов её не меняет. Текущая работа завершается, следующий запрос начинает новую сессию.

Отклонённый ввод сохраняется до изменения эффективной ревизии workflow. Исправив неизвестный профиль, шаблон или сервис, увеличьте `revision` и примените настройки. Коннектор повторит ввод без перезапуска. Повторные уведомления об отказе подавляются для одной ревизии, причины и ввода.

## Удаление workflow

Сначала задайте [`draining: true`](../../reference/mattermost.md#workflow-draining). Коннектор перестанет принимать новые задачи и доставит принятые результаты. Дождитесь завершения, затем удалите файл и примените конфигурацию. Немедленное удаление может отменить активную работу. Бот выходит из приватных каналов, для которых больше нет подходящего workflow. Отключение доступа к приватным каналам приводит к тому же результату.

Для одного сервера Mattermost и бота запускайте один экземпляр коннектора. При обновлении заменяйте его последовательно.

## Восстановление после простоя {#recovery}

При запуске или перечитывании workflows история каналов читается от [`reconcile_from`](../../reference/mattermost.md#workflow-reconcile-from). Последующие проходы проверяют сообщения, созданные за последние семь дней, но не раньше `reconcile_from`. Сюда входят новые ответы в старых тредах. Каждый найденный тред загружается целиком.

Поиск сессий Orpheus использует время создания последнего запуска: первый успешный проход после старта или перечитывания охватывает 21 день, последующие — семь. Эти окна не зависят от срока хранения песочницы. Уже известные активные задачи и недоставленные ответы продолжают отслеживаться за пределами окон.

После потери доступа к каналу более чем на семь дней или пропущенного события редактирования старого сообщения периодическая сверка может не найти задачу. Её может обнаружить новое событие треда или проход после запуска/перечитывания. После долгого простоя проверьте затронутые треды. Новые события получают приоритет перед восстановлением архива, при этом восстановление продолжается в общем пуле обработчиков.

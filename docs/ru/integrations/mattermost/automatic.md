# Канал с автоматическим запуском

Для канала входящих задач создайте специализированный workflow и отключите требование упоминания при старте:

```yaml
include_ids:
  - INBOX_CHANNEL_ID
start_on_mention: false
```

Это фрагмент YAML, который нужно добавить к полному [workflow канала](channels.md). Каждый подходящий новый тред запускает задачу без `@orpheus`.

Если сообщения-треды в канале создаёт внешний бот или webhook, разрешите его ID:

```yaml
trigger_bot_ids:
  - SOURCE_BOT_ID
```

Сам бот коннектора может запустить задачу **новым корневым сообщением** с явным упоминанием своего текущего имени, например `@orpheus Обработай задачу A`. Правило действует во всех типах каналов, включая личные сообщения, независимо от `start_on_mention` и `trigger_bot_ids`. Ответы бота внутри тредов обработку не запускают.

Так агент по расписанию может создавать независимые задачи в канале от имени бота. Каждый корневой пост использует workflow канала. Не задавайте инструкции бесконечно создавать новые корневые посты: ограничение на корневые сообщения не ограничивает длину намеренных цепочек.

## Продолжение разговора

[`start_on_mention: false`](../../reference/mattermost.md#workflow-start-on-mention) меняет запуск нового треда. Для следующих обращений в канале упоминайте бота или используйте [настроенное имя](workflow.md#trigger-names). Личные сообщения обрабатываются без упоминания, если включён [`direct_messages`](../../reference/mattermost.md#workflow-direct-messages).

Для сбора нескольких последовательных сообщений можно задать [`message_batch_window: 3s`](../../reference/mattermost.md#workflow-message-batch-window). Окно начинается с первого ещё не принятого сообщения. При `0` запуск начинается сразу.

Проверьте автоматический канал отдельной тестовой задачей и убедитесь, что он не пересекается с другими специализированными workflows.
